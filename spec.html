1. 视觉设计系统定稿（Design Tokens）

1.1 色彩系统与 RGB565 硬件量化账本

IT9868 显示链路输出为 RGB565（R:5 bit, G:6 bit, B:5 bit）。固件 LVGL 8.3.7（sdk/share/lvgl/src/misc/lv_color.h:150）采用高位截断移位宏 LV_COLOR_MAKE16(r,g,b)：((r >> 3) << 11) | ((g >> 2) << 5) | (b >> 3)。下表与原型均严格按同一 LVGL 移位口径复算（22/22 零误差），UI 代码在 ui_theme.h 中统一按 Token 定义，禁止散写硬编码色值。

1.3 栅格、圆角与触控反馈规范

  • 基础模数：8 px。页面安全外边距 24 px，卡片内边距 16 px，卡片间距 16 px（竖屏双行卡片横向间距取 20 px，见 3.1 节图片上限推导）。
  • 圆角：设备卡片 12 px、普通按钮 12 px、Toast 12 px、状态胶囊 999 px（半高 22 px）、视频区与分区容器 0 px。
  • 触控热区（C10）：所有可点击控件外框不小于 64×64 px，相邻热区外边缘间距 >= 16 px。文字较短的图标按钮通过透明内边距扩展热区。
  • 按下反馈（LV_STATE_PRESSED）：过渡时长 50 ms（或不设渐变即时响应），背景色切换为 surface_hi（纯文字/透明底控件切换 bg_opa = LV_OPA_70），松手立即恢复。严禁使用 transform_zoom 缩放反馈。

2. 导航架构、手势裁决与状态机

2.1 左上角 100×100 维护热区与返回按钮避让规范

规格 6.2 节规定：任意页面左上角 (0, 0, 100×100) 区域 3 秒内连点 5 次进入维护页，该区域内不得放置返回按钮或其他可点控件。

  • 在 lv_layer_top() 常驻一个 100×100 透明无背景对象 maint_hotspot（x=0, y=0），维护页自身激活时隐藏该热区（避免重复入栈），退出维护页时恢复。
  • 点击时间戳环形队列记录最近 5 次 LV_EVENT_CLICKED 的 lv_tick_get()，当 t[4] - t[0] <= 3000 ms 时清零队列并压入维护页。

  2. 监听输入设备任意 LV_EVENT_PRESSED / LV_EVENT_PRESSING 重置倒计时为 model->idle_timeout_s（缺省 60 s）。
  3. 挂起条件：当前处于 Detail 页且激活标签为 model3d 或 intro，并且 hal_video_is_playing() == true 时，暂停倒计时递减；视频触发 EOS（播完停在末帧显示重播按钮）或切换到 图片 标签时，立即从完整 idle_timeout_s 恢复倒计时。
  4. 触发动作：若当前有正在播放的视频先调 hal_video_stop()，清空页面栈，以 200 ms 透明度过渡重建并回到 Idle 页。

C2屏幕物理分辨率 1280×800，RGB565竖屏布局由显示驱动旋转成 800×1280。UI 代码只按 lv_disp_get_hor_res/ver_res 返回的逻辑分辨率排版，不能写死方向
C3同一时间只能播一路视频视频由 hal_video_bind_viewport(parent, rect) 加 hal_video_play_file(path, vol) 播放，画面作为一个 LVGL 图片对象画在 parent 里。切换页面前必须先调用 hal_video_stop()
C4视频区可以叠加控件，但要少视频每一帧都会让它所在的区域重绘，叠在上面的控件也跟着每帧重画。叠加的控件只允许一条不透明或半透明的字幕条，高度不超过 64 px，不能叠加阴影或渐变
C5动效白名单只能用平移、透明度和帧动画。不能做旋转或缩放动画（lv_img_set_zoom 只能用来做静态适配）。单个动效不超过 300 ms。不能有整屏持续变化的动效（例如背景流光、粒子效果）
C6禁用高开销样式尺寸大于 200×200 的对象不能设 shadow_width；不能用模糊；渐变只允许用在高度不超过 80 px 的条带上。圆角可以使用
C7图片后台已经把图片处理成 baseline JPEG（封面 800×450、卡片 360×240、画廊不超过 800×800），或者带透明通道的 PNG。UI 只做静态缩放适配（见 ui_cabin_v2.c 里的 fit_img_zoom），不做其他处理
C8内存图片缓存走 IT2D 的 8 MB LRU。同一屏幕上同时可见的图片不超过 8 张；卡片列表必须懒加载，滑出屏幕的卡片要释放图片源（lv_img_set_src(NULL) 或者删除对象）
C9字体用 FreeType 加载 B:/font/wqyMicroHei.ttf，这套机制在 v2 里已经实现（ui_theme_init_fonts）。这个字库实测覆盖 GB2312 汉字 6762/6763。字号只能用第 3.2 节规定的 5 档
C10触摸单点触摸，没有多点手势。可点击区域不小于 64×64 px，相邻两个可点击区域至少间隔 16 px
C11线程只能在 LVGL 线程里调用 lv_*。清单更新、布局切换这类通知由 biz_core 通过 lv_async_call 投递到 LVGL 线程

5.2 媒体区

  • 标签：图片（gallery，以及作为第一张的 cover）、3D 演示（model3d）、介绍视频（intro）。只显示有内容的标签；一个都没有时，媒体区显示占位图"暂无图片和视频"，标签栏隐藏。
  • 默认标签：有 3D 演示就默认进 3D 演示，否则进图片标签。
  • 图片标签
  • 左右滑动切换图片，下方的缩略图条可以直接点选。
  • 5 s 无操作就自动切到下一张，切换用 200 ms 淡入淡出。
  • 图片按 contain 方式适配，空白处填 bg 色。
  • 一台设备最多显示 12 张图片。
  • 视频标签
  • 进入标签就开始播放，播完停在最后一帧，显示一个居中的"重播"按钮（96×96）。
  • 同一个标签下有多个视频时，依次播放。
  • 离开这个标签或页面时，必须调用 hal_video_stop()。
  • 进入详情页前要先停掉待机页的视频；回到待机页后，从当前视频的开头重新播放。

5.3 交互

  • 切换设备：在右侧信息区（竖屏时是下方的信息区）左右滑动，或者点"上一台/下一台"按钮，就切换到相邻的设备，顺序和待机页卡片一致，首尾循环。过渡是 250 ms 平移。
  • 滑动冲突：在媒体区内左右滑动是切换图片，不是切换设备。
  • 返回：点返回按钮，回到进入详情页之前的那一页。
  • 字段规则：参数表的数据来自 specs 数组，原样显示。intro 用 f_body，最多显示 2000 字，超出部分截断并加"…"。

6.2 维护页

  • 进入：在任意页面的左上角 100×100 区域内，3 s 内连点 5 次。这个区域不能有其他可点的控件，返回按钮不放在这里。

7. 状态和边界情况

场景必须的行为
收到新清单（commit 成功）用户在待机页时：直接按新数据重建页面。用户在详情页或介绍页时：如果当前查看的设备还在，就留在当前页刷新数据，并提示"内容已更新"；如果这台设备已被移除，就回到待机页，并提示"内容已更新"
收到 set_layout关闭抽屉和弹层，清空页面栈，按新布局重建待机页。方向变了时先让显示驱动完成旋转，再重建页面。整个过程不超过 3 s
清单里引用的文件不存在图片显示占位图，视频跳过。不能崩溃，不能卡住
文本超长每个文本控件都必须规定最大行数并加省略号，或者放在可滚动的容器里。不能有文字溢出到区块外面
字库里没有的字FreeType 会显示成方框。后台录入时会校验这类字，固件不做额外处理
0 台设备、0 个媒体按前面各节写的空状态显示，页面结构不变
很快地连续点击页面跳转期间（250 ms 内）忽略新的跳转请求，避免同一个页面被打开两次

6. 验收清单

  1. 三种角色分别登录：看到的菜单和按钮符合第 2 节的权限表；直接调用无权限的 API 返回 403。
  2. 一条完整流程走通：新建实验室 → 新建 3 台设备并上传媒体，其中一个视频需要转码 → 组合设备 → 绑定 PC 模拟器（或真板）→ 选择布局 → 预览 → 发布 → 平板显示正确。
  3. 把一台设备从 A 实验室移到 B 实验室：要求二次确认，两个实验室都变成"待发布"，历史表里有记录。
  4. 录入超长文本、平板字库里没有的字，都有对应的校验和提示。
  5. 在发布过程中拔掉平板网线：任务失败并给出原因；恢复网络后点"重试"，已传完的文件被跳过。
  6. 在 1366×768 分辨率下，所有页面都没有横向滚动条，没有元素重叠。

  {"code": 0, "msg": "ok", "data": { ... }}
  • code 为 0 表示成功；非 0 时，HTTP 状态码和 code 一致（400/401/404/409/413/415/507/500），msg 是可以直接展示给用户的中文说明。
  • 字符编码：UTF-8。
  • 并发：平板的网页服务是单线程的。后台对同一台平板的请求必须串行。不同平板之间可以并发，默认最多 4 台。

2.3 upload

  • 请求格式：POST ...?action=upload&name=<文件名>&sha256=<hex>，请求头 ContentSize: <字节数>，multipart/form-data 的字段名为 file。上传方式和视频机一致。
  • 文件名规则：只能用 [A-Za-z0-9._-]，最长 64 个字符。后台统一用 <sha256 前 16 位>.<扩展名> 命名，避免中文文件名和重名。
  • 处理流程：
  • 写入暂存区；
  • 校验大小和 sha256，不一致返回 400；
  • 检查格式。图片必须是 baseline JPEG 或 PNG，且不超过 1920×1920，否则返回 415 或 413。视频必须是 MP4 封装的 H.264；
  • 移入素材区。
  • 剩余空间不够时返回 507。
  • 同名、同 sha256 的文件已经存在时，直接返回成功（幂等）。

  "version": 12,

  "lab": {
    "id": "L1", "code": "L3-201", "name": "材料力学实验室", "status": "使用中",
    "location": "3号楼 2层 201", "owner": "张老师", "phone": "…",
    "open_hours": "周一至周五 8:30-17:30",
    "intro": "…", "safety": ["进入实验室须穿戴防护用品", "…"],
    "media": [{"file":"a1b2….jpg","role":"cover"},{"file":"c3d4….mp4","role":"intro"}]
  },
  "equipment": [
    {"id":"E17","asset_no":"…","name":"万能试验机","model":"…","vendor":"…",
     "status":"可用","intro":"…","specs":[["量程","300 kN"],["精度","0.5 级"]],
     "media":[{"file":"…jpg","role":"cover"},{"file":"…mp4","role":"model3d"}]}
  ],
  "ui": {"idle_timeout_s": 60, "theme": "default"}
}
  • media[].role 的取值：cover、gallery、model3d、intro。
  • manifest_sha256：后台对规范化清单内容计算的 SHA-256，用于幂等判定与回读核验。
  • 平板的处理流程（严格顺序，防止删除播放中素材）：
  • 身份与版本校验：
  • 若本机尚无清单（current_lab_id == ""）：直接放行；
  • 若 lab.id == current_lab_id（同一实验室更新）：
  • version == current_version && manifest_sha256 == current_sha256：视为重复提交，幂等返回 200（不重复删文件或重建界面），解决提交回包丢失后重试报 409 的问题；
  • version <= current_version 且哈希不一致：返回 409，除非请求带 force=1；
  • 若 lab.id != current_lab_id（平板从 A 实验室换绑到 B 实验室）：
  • 未带 force=1：返回 409（msg: "平板当前绑定了其他实验室，换绑发布需显式替换"）；
  • 带 force=1（显式替换流程，推荐同时传 expected_lab_id 防止并发误覆盖）：若 expected_lab_id 非空且不等于 current_lab_id 返回 409，校验通过后允许以 B 实验室的 version（如 v1）直接替换 A 实验室（如 v12）。
  • 检查清单引用的所有文件都已存在。缺文件时返回 400，并在 data.missing 里列出缺少的文件。
  • 原子持久化新清单（写入临时文件或 A/B 双槽位并 fsync + 校验通过后切换生效指针），中途断电不会损坏旧清单。
  • 先通知 UI 切换并等待释放旧句柄：通过 lv_async_call 通知 LVGL 线程立即调用 hal_video_stop()、释放所有旧图片引用、按新清单重建页面；等待 UI 线程置位切换完成信号（超时保护 3 s）。
  • UI 确认切换完成后，再删除不再被新清单引用的旧素材，避免播放或硬解线程持有已删文件句柄。
  • 成功时返回：
json
  {"code":0,"msg":"ok","data":{"lab_id":"L1","manifest_version":12,"manifest_sha256":"e3b0c442…","removed":3}}

2.6 set_layout

请求体：

json
{"layout": "portrait_std"}
  • 平板的处理：
  • 检查 layout 是否在 layouts 列表里。不在时返回 400，msg 为"不支持的布局"。
  • 把布局 id 保存到 NAND 配置；
  • 不重启，直接按新布局重建界面。如果方向变了，屏幕旋转和触摸坐标跟着一起切换。
  • 正在播放的视频在新的视频区里重新开始播放。
  • 成功时返回：
json
  {"code":0,"msg":"ok","data":{"layout":"portrait_std","orientation":"portrait","w":800,"h":1280}}
  • 布局和当前一致时直接返回成功（幂等）。
  • 布局不属于清单内容。切换布局不需要重新发布，清单版本也不变。
  • 固件升级后，如果保存的布局 id 已经不存在，就回退到 default，并在 info 里如实反映。

3. 同步流程（后台侧）

冻结发布快照 (snapshot_id: lab_id + version + sha256 + panel_id + binding_rev)
  → GET files → 比较得出缺少的文件 → 检查剩余空间
  → 逐个 upload（已存在且 sha256 一致的跳过）
  → commit（跨实验室换绑时显式带 force=1&expected_lab_id）
  → GET info 回读核对 (lab_id, manifest_version, manifest_sha256)
  • 不可变快照：预检（publish/plan）、预览（preview-bundle）和发布（publish）共用同一个 snapshot_id。若期间实验室被他人保存产生新版本，或平板发生换绑导致 binding_rev 变化，旧快照发布必须明确阻断或按原快照执行并标注目标快照信息，绝不静默推送未经确认的新内容。
  • 断点续传：以文件为单位。上传阶段中断后按任务 ID 重试，已上传且 sha256 一致的文件会被跳过。
  • 失败与未知状态（待核验）区分：
  • upload 阶段或 commit 返回明确 4xx/5xx 失败：任务标为「失败」并记录 msg，平板继续显示旧清单。
  • commit 已发出但网络断开/回包超时，或 GET info 回读超时：由于平板可能已原子落盘新清单，后台不得武断标记“屏幕仍为旧版”，而应将任务标为「待核验 (unverified)」。后台轮询或用户点击「重新核验 / 重试」时：
  • 先执行 GET info 比对 (lab_id, manifest_version, manifest_sha256)；若三者均与目标快照一致，直接将任务收敛为「成功」；
  • 若平板仍为旧清单，再重发同一快照 commit（即使平板此前恰已落盘，平板按 2.4 节幂等规则返回 200 确认）。
  • 改密回包丢失恢复（set_password）：发起改密前后台先将加密后的 pending_password 持久化入库；若 set_password 超时无回包，重试时先用旧密码探活，若返回 401 则自动使用 pending_password 校验 layouts/files，通过即正式转正为当前密码并清除 pending_password。
